# Mac 客户端文件凭据方案

## 上下文

范围为 AgentWork Mac 远程客户端的连接保存和启动恢复。用户于 2026-11-08 确认采用文件方案并在 develop 实施；调用来源为本次客户端凭据改造任务。现有实现见 `apps/desktop/src/remote-desktop.ts`；服务端 Cookie 签发和有效期见 `packages/client/connection/src/browser-auth.ts`。

## 决策

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 系统钥匙串 | 操作系统按应用保护加密密钥 | 开发签名更新可能重新要求授权 |
| 私有文件（已选） | 首次连接后自动恢复，不访问钥匙串 | 同一用户的其他程序可能读取凭据，备份须排除凭据文件 |
| 仅内存 | 不保存长期凭据 | 每次打开应用都需重新输入访问令牌 |

Mac 客户端在 `~/.agent-work/client/` 保存版本化的地址配置和会话 Cookie；目录权限为 `0700`，文件权限为 `0600`。只保存已验证服务端签发且带有效期的 Cookie，不保存首次输入的启动令牌或服务端签名密钥。Cookie 仍是有权限访问后端的凭据，文件方案不能保护它免于同一用户的其他程序读取；不采用同目录保存密钥和密文的额外加密层。

原配置只迁移服务端地址，不解密旧的 `encryptedCookie`，首次连接重新输入访问令牌。保留旧文件和钥匙串记录。文件损坏、权限异常或写入失败必须阻止连接激活，并在保留本地工作台和设置的同时报告可恢复错误；不将存储失败当作连接成功。

凭据绑定精确源站，过期不复用，切换地址不会向其他服务端发送原凭据。认证和 TLS 保留；Windows 原有系统凭据存储和 iOS 行为保持其现有实现。检查 Chromium 会话的间接钥匙串访问，不通过关闭证书校验或系统安全机制解决弹窗。

## 验证

覆盖首次保存、重开恢复、过期、地址隔离、旧地址迁移、坏文件/权限/链接拒绝和写入失败。通过原生主进程的连接流程验证不调用 Mac safeStorage，并实际检查本地界面和设置。新增持久化目录及重新认证要求写入升级指南；正式发布独立执行，不覆盖现有预发布资产。

## 依据与确认

[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage) 说明钥匙串保护和签名更新的授权行为；[Electron Session](https://www.electronjs.org/docs/latest/api/session) 说明持久化与内存浏览器会话的区别。方案已获用户明确确认，无待定存储选型。
